# TUI 启动欢迎页设计

## 背景

当前 Ink TUI 启动后直接显示空消息区、输入框和状态栏，缺少明确的产品标识与启动状态。目标是在不改变 Agent 会话、工具调用、确认流程和流式渲染的前提下，增加一个接近参考图视觉结构的欢迎面板。

## 已确认范围

- 欢迎面板只在启动后的空会话显示。
- 用户首次提交内容后，欢迎面板让位给消息区，不再显示。
- 宽终端使用左右双栏，窄终端自动改为上下排列。
- 右侧只显示使用提示与当前会话空状态，不读取或持久化历史活动。
- 保留现有消息、任务、确认、输入和状态栏行为。

## 非目标

- 不新增会话历史文件或最近活动读取逻辑。
- 不新增 `/init` 等当前未实现的命令。
- 不修改 Agent runtime、事件协议、消息模型或工具调度。
- 不重构与欢迎页无关的 TUI 组件。
- 不展示版本号。项目当前没有供 TUI 直接复用的运行时版本来源，本次避免硬编码版本或扩大到打包层。

## 组件设计

新增 `src/tui/components/WelcomePanel.tsx`，职责仅限欢迎页渲染与终端宽度适配。

组件接收：

- `workingDirectory`：当前工作目录。
- `model`：当前模型标识。

`App.tsx` 继续负责视图组合。只有以下内容全部为空时才渲染 `WelcomePanel`：

- `displayLog.staticEntries`
- `displayLog.pendingEntries`
- `displayLog.streamingBlocks`

用户提交后会产生用户消息，因此不需要新增 `hasStarted` 等重复状态。

## 视觉结构

欢迎面板使用单层粉红色边框，标题为 `mini-cc`。

左侧包含：

- 欢迎文案。
- 简洁的字符标识。
- 当前模型。
- 当前工作目录。

右侧包含：

- “使用提示”：输入任务后按 Enter 提交。
- “当前会话”：暂无活动。

欢迎面板下方保留输入区与状态栏。输入区增加分隔线和灰色提示文本，状态栏继续使用现有目录、模型、步骤、上下文占用和执行状态数据。

不在页面中加入未实现能力或额外快捷键说明。

## 响应式行为

`WelcomePanel` 通过 Ink 的 `useStdout()` 获取 `stdout.columns`，并监听 `resize` 事件更新宽度。

- 宽度大于或等于 `80` 列：左右双栏。
- 宽度小于 `80` 列：右侧移动到左侧下方。
- 无法读取宽度时：按 `80` 列处理。

模型名和工作目录使用中间截断，避免长文本撑破边框。布局判断保留为组件文件内的纯函数，便于测试，不新增单独的通用布局模块。

## 数据流与清理

`App` 从现有配置获取模型标识，并将模型与工作目录传给 `WelcomePanel`。欢迎组件不读取 Agent 状态，也不写入本地文件。

组件挂载时订阅 `stdout` 的 `resize` 事件，卸载时移除监听，避免重复订阅。终端宽度变化只影响欢迎面板布局，不影响消息与会话状态。

## 测试方案

新增 `test/tui/WelcomePanel.test.tsx`：

- 展示品牌、模型、目录、提示和空会话文案。
- 宽度边界函数在 `79` 列返回单列，在 `80` 列返回双栏。
- 长目录使用中间截断，并且渲染行不超过测试终端宽度。

更新 `test/tui/App.test.tsx`：

- 空会话显示欢迎面板。
- 首次提交后欢迎面板消失。
- 原有用户消息、模型回复、确认弹层和流式输出断言继续通过。

按风险依次验证：

1. `bun test test/tui`
2. `bun test`
3. `bun run typecheck`
4. `bun run build`
5. `git diff --check`

## 验收标准

- 启动空会话时呈现粉红边框的响应式欢迎面板。
- `80` 列及以上为双栏，低于 `80` 列为单列。
- 首次提交后只显示原有对话工作流，不再显示欢迎面板。
- 不产生会话历史或其他新持久化文件。
- 现有 TUI 行为和测试无回归。
